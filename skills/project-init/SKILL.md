# 分析项目初始化

## 先判断任务与授权

目标是建立最小可用项目入口，而不是生成整套分析或自动安装环境。仅讨论流程时只解释，不创建文件。要求初始化时执行下述流程；只有用户同时明确授权后续分析，才在初始化后继续。

规则仓库路径/URL不等于目标项目路径。目标位置不明确时先问。遵守宿主指令和权限，Skill 不提供额外授权；无法读取资源或遭拒绝时报告并请求用户决定，不绕过权限。

## 必须读取的资源

初始化前完整读取 [项目规则模板](assets/AGENTS.template.md)、[项目说明模板](assets/README.template.md) 和 [阶段计划模板](assets/PLAN.template.md)。需要暂停或交接时才读取 [交接模板](assets/HANDOFF.template.md)。模板与本 Skill 同一版本，远程读取时所有资源使用同一 tag/commit；不可用时不凭记忆重建。

项目规则模板也是本 Skill 执行时的通用约定。目标项目已有规则或用户要求与模板冲突时，说明差异并按明确授权合并；不要用模板覆盖现场。符合上级指令的、用户明确确认的项目例外应保留。

## 执行流程

1. **读取现场**：查看目标目录；若存在，先读 AGENTS、README、当前阶段 PLAN/HANDOFF。没有证据不假定空项目。只在相关范围内递归发现文件，不扫描整个磁盘或加载大型产物。
2. **补关键缺口**：确认目标、指定数据、期望交付及本轮授权。已有明确答案直接沿用，不重复问。数据不明确时不自行选数据。尚未决定但不阻塞结构初始化的字段写“待确认”。
3. **轻量核对**：按本轮需要检查数据说明、规格、标识、环境和有效会话状态。环境优先使用宿主提供的检查能力，已有有效检查复用。不默认读大对象、安装包、建环境、切换语言或清空会话。
4. **建立最小结构**：在目标项目实例化 AGENTS.md、README.md、step1/PLAN.md，按需建立 data/、step1/scripts/、step1/output/。实际阶段可能不是 step1，接续已有阶段，不重置编号。不搬移、复制或回写原始数据；已在外部位置的数据记录来源即可。
5. **实例化而非盲复制**：填入已确认事实；未确定项标待确认。规则模板的来源信息记录实际仓库地址、本地来源或准确版本；无法取得 commit 时注明未记录，不编造。README 链接到实际阶段；只有明确授权才将 PLAN 标为可执行。
6. **保护既有内容**：首次初始化只写不存在的目标文件；重复初始化先比较，只补已授权且无冲突的缺失内容。有冲突先说明再合并；修改前保留可恢复旧版，不仅保留哈希。不得复制本仓库维护用 AGENTS 代替项目模板。
7. **验收并停在正确位置**：检查新文件、相对链接、目标位置、授权状态及未填字段。新增/修改文件按规则登记实际来源和 SHA256；初始化文件可登记在当前阶段 output/MANIFEST.tsv，不生成虚假计算产物记录。不要提前生成后续阶段、空报告或空 HANDOFF。说明已创建、未改动、待确认与下一动作；只初始化则到此停止。

## 后续读取与专题 Skill

目标项目保留自包含规则快照，不依赖每次联网。新会话按 AGENTS → README 当前入口 → 当前阶段 PLAN/HANDOFF → 必要脚本、日志或轻量产物读取。旧交接的内存状态须重新轻量核对。

方法需求出现后才读本规则仓库 README 中匹配的专题 Skill；若尚无匹配 Skill，说明没有，不自行宣称已加载或生成新方法流程。记录实际使用的来源版本。读取 Skill 不代表批准其中全部计算；用户确认边界仍有效。

## 结果反馈边界

不显著或无预期趋势时，如实汇报、提出有依据的调整方向并询问用户，不自行更换基因集或反复尝试，也不直接终止所有探索。获准后保留旧结果，记录探索性调整及尝试范围，仅重算受影响部分。统计解释遵循模板约定。

## 完成判据

文件真实存在、规则与计划授权一致、入口能定位、无意外覆盖或计算、实际检查有记录。完成初始化不等于分析完成；静态文件检查不等于已经验证新会话 AI 的行为。
