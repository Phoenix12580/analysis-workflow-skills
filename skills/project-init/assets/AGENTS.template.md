# 分析项目协作约定

规则版本：0.1.0。来源仓库/本地路径：待填写。来源 tag/commit：待填写；无法取得时注明未记录。采用日期：待填写。

本文件是目标项目的本地规则快照，不自动追随远程更新。具体目标、方法和参数写入阶段 PLAN；已确认的项目例外写在文末。不绑定本模板来源项目的算法、数据或运行环境。

## 1. 入口与范围

先读本文件、README 中的当前阶段入口，以及该阶段 PLAN/HANDOFF，再按本轮任务读取必要脚本、日志和产物；不每次全盘搜索。历史交接中的内存状态只代表当时，使用前轻量核对。

每轮区分查询、计算、出图、改标签、排错或交接，明确交付与停止位置。阶段开始前将已确认的目标、输入、方法、参数和预期输出写入 PLAN；未确认项不能写成已授权。明确交付任务在授权内完成；开放探索分段反馈，不自动铺开全部后续分析。

授权范围内的读取、保存、导出和不改变分析含义的技术修复直接执行，不逐项确认。未经授权的样本、表达层、基因集、分组、阈值、算法或资源范围实质变化，先说明影响并询问。标签排版与已确认的一一对应改名属于展示；改变归属、合并类别或生物学定义属于分析决策。交接中的建议不等于授权。

简洁中文沟通，先说明当前发现和下一动作，不夸大结论；相关轻量检查合并，避免大量细碎调用和冗长播报。

## 2. 目录与最小读取

原始输入只读，不回写 data/，不擅自搬移或复制外部原始数据。按 stepX/scripts/ 和 stepX/output/ 组织脚本与产物，输出的 data/、figures/、tables/、logs/ 按需创建。不预建整套未来阶段。

先确定最低数据需求，再依次选择有效内存对象、匹配的轻量缓存、按需读取的保存结果，最后才补算缺失或失效部分。复用前核对来源版本、范围、参数、唯一标识及顺序；不凭对象同名或文件存在判断有效。不为查字段、样本组成或改图先加载整个大对象。

必要时保存带唯一标识与来源版本的元数据、坐标、标签和对象规格；相关输入变化时更新，不重复生成无关缓存。优先复用指定语言、当前环境和已有有效包/接口检查，不默认跨语言或安装整套环境。

## 3. 参数、结果反馈与确认

用户指定参数和扫描范围优先，不擅自扩展、替换或缩减。未指定时先核对方法适用性及安装版本的默认参数，以默认配置完成一轮基准，不自行增加扫描或多套方案。默认配置若耗时或资源需求高，先说明并确认首轮范围；自定义参数不能称为默认。

结果不显著或没有预期趋势时，如实汇报当前结果及局限，提出有依据的可选方案，并询问用户是否更换基因集、调整方案或继续探索。不自行连续尝试，也不直接终止所有探索。获准后记录调整理由、参数与尝试范围，保留原结果，只重算受影响部分。

根据已观察结果作出的调整标为探索性；多方案尝试应记录，必要时考虑多重比较或独立验证，不只保留显著结果。区分计算结果、展示选择和科学解释；记录矛盾先说明，不凭预期补齐结论。

## 4. 执行、进度与恢复

按真实依赖、资源与失败恢复成本拆成可独立执行的短模块；轻量操作合并，共同输入复用，不给每个函数单独存盘。耗时模块在恢复成本高的边界保存检查点，包含来源、参数、适用种子、必要包版本及足够恢复的输出，优先沿用项目已有保存格式。

耗时读取、计算、保存分别显示模块、开始、结束/失败、已用时与输出位置；启用原生进度，有总项数时显示当前项/总项。无真实比例不伪造百分比或剩余时间，输出缓冲时提供日志位置，不因无新输出重复启动计算。

失败或中断先检查运行状态、有效对象与检查点，只恢复失败模块和确实失效的下游。图形失败只修图，不清空后从头 source；已有任务运行不启动第二份。同一错误反复出现且无新的诊断依据时停止盲目重试，说明阻塞原因。改变结果的临时操作补回相应脚本，旧版本保留。

## 5. 保存与内存分开决定

核心结果先保存验收，再独立生成图表。保存成功不意味着立即释放内存；保留当前仍需使用的对象。不把全清环境、重启语言会话或重载完整对象作为脚本固定动作。

新高内存任务前，检查必要对象、重复副本及可用资源，按实际需要定向清理；已保存且不再需要的临时对象无需逐一询问。无法可靠测量时说明限制，不假报已释放。用户要求结束/清理、对象不再需要或资源不足时，确认可恢复后再清理，不为节省资源擅自抽样、降低精度或缩减计算。

## 6. 图形与精修

顺序是保存并汇报结果 → 简单可读初图 → 用户选定及给出方向 → 精修与交付。初图复用同一绘图对象直接输出同名同版本 SVG、PNG、PDF，不先做出版级排版，不事后用 PDF/PNG 转换冒充原生 SVG。保留文字、坐标和图例可编辑；必要时按约定局部栅格化大量散点，不整图栅格化。缺格式仅补缺失项，不重算上游。

每张选定图或组图最多两轮审美精修，一轮满足即可停止；换工具、拆图、改名或格式不重置次数，额外美化需用户明确要求。两轮约束审美，不是交付错误的理由：标签、对应关系、可读性或导出缺陷需在范围内修复，或明确标记未完成。不得把普通美化包装成必要修复无限继续。

改标题、配色、尺寸、编号和格式不重算上游。只在输入、计算参数、相关代码改变或已有结果失效时，明确影响模块并重算。

## 7. 验收、停止与交接

实际交付和必要检查通过后停止，不自动新增分支。需要关键决策、输入缺失或含义不明、资源风险超出约定、恢复受阻时暂停受影响部分，报告所需决策；独立且已授权的部分可继续。用户取消时不启动新任务，说明运行任务真实状态并安全停止或保留检查点，不把取消当完成。

脚本和产物递增版本，核心冻结结果不因标签或样式改动反复覆盖。output/MANIFEST.tsv 记录实际路径、版本、生成时间、真实源脚本或生成方式、SHA256、原因和当前/被替代状态；哈希不代替旧版备份。仅新增或修改内容登记新哈希，不因普通查询遍历全部大文件；清单不对自身递归哈希。改名同步引用并验证。

写好代码不等于运行成功，停止计算不等于任务完成，完成不等于必须清空。PLAN 记录共识、变更和简短状态；HANDOFF 在阶段结束、暂停或切换会话时记录当前产物、已通过检查、取消/未完成项、下一动作和带时间的实际内存状态。顶部状态与正文同步；文档整理不触发重算。
